# @repo/db

Kysely + Postgres. **Source-only** — exports `./src/index.ts` and
`./test-support` directly (no build step; picked up live in dev).

## Layout

- `src/client.ts` — validates `POSTGRES_*` via `@repo/env` `parse()`, builds a
  `pg.Pool` (max 10), exports `db` (`Kysely<DB>`) and `pool`. Sets a pg type
  parser for OID 1082 (`date`) so dates stay raw `YYYY-MM-DD` strings.
- `src/migrate.ts` — Kysely `Migrator` + `FileMigrationProvider` over
  `src/migrations`, `migrateToLatest()`. Run via `pnpm migrate`.
- `src/migrations/*` — `YYYYMMDDTHHMMSS-kebab-desc.ts`, each exports `up`/`down`.
- `src/types.ts` — **GENERATED by kysely-codegen. Never edit by hand.** Re-run
  `pnpm migrate:generate` after schema changes.
- `src/index.ts` — re-exports `db`/`pool`, `DB` + table types, and
  `XxxRecord = Selectable<Table>` / `NewXxx` / `XxxUpdate` aliases.
- `src/test-support.ts` — faker factories + `truncateAll` for tests.
- `.kysely-codegenrc.json` — maps `CHECK (col IN (...))` columns to literal
  unions (e.g. `user.role → Generated<'admin' | 'agent'>`). Inline literals only
  — never import from `@repo/trpc` (circular).

## Conventions

- Data records carry `created_at`/`updated_at` (and `deleted_at` on app tables).
- Use `Selectable`/`Insertable`/`Updateable`, never inline record types.
- Auth tables are snake_case; the app-side Better Auth config maps its camelCase
  fields onto them.
- Migration/seed scripts log via `console` (standalone CLIs that must run without
  the built `@repo/logging` artifact).
