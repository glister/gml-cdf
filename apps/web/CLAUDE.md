# @repo/web

TanStack Start + React 19 (SSR). Vite for the client/SSR build; tsup builds the
prod Node server.

## Key files

- `vite.config.ts` — plugin order matters: `env-check` (parses `VITE_API_URL` in
  buildStart) → `tailwindcss()` → `tanstackStart({...})` → `tsconfigPaths()` →
  `react()`. Port 3000, host 0.0.0.0, `fs.allow: ['../..']`. `@repo/*` in
  `optimizeDeps.exclude` (raw TS).
- `src/router.tsx` — exports **`getRouter()`** (not createRouter). Builds a
  QueryClient; `{ session, queryClient }` in RouterContext.
- `src/routeTree.gen.ts` — auto-generated by the router plugin. **Never edit.**
- `src/entry-client.tsx` / `src/entry-server.ts` / `src/server.prod.ts` — client
  hydration / SSR handler / prod Node server (serves `dist/client` + SSR
  fallthrough, listens on PORT).
- `src/trpc.ts` — vanilla `trpc` (loaders/tests) + `trpcReact` (components). SSR
  uses `API_INTERNAL_URL`, browser uses `VITE_API_URL`; `fetch` forces
  `credentials: 'include'`.
- `src/auth-client.ts` — better-auth react client with `adminClient()` +
  `emailOTPClient()`.
- `src/lib/resolve-session.ts` — SSR session via a `createServerFn`.
- `src/lib/route-guards.ts` — UX-only gates (real enforcement is in `@repo/trpc`).
- `src/routes/` — file-convention routes: `__root`, `login`, `index` (→
  dashboard), `_authenticated/` group + `dashboard`.
- `src/env.ts` (isomorphic public `import.meta.env` VITE_ vars — safe in
  server-reachable routes/loaders) / `src/env.server.ts` (lazy, server-only
  secrets; `.server.` is import-protected from the client bundle). Note: an
  isomorphic public-env module must **not** be named `*.client.*` — TanStack
  Start's import-protection forbids `.client.` imports in the server environment.

## UI — design system (mandatory)

Every screen follows the **CD Fencing Design System** (root `CLAUDE.md`; Claude
Design project read via DesignSync): tokens, component prop contracts
(`components/<domain>/*.d.ts` + `.prompt.md`) and the `ui_kits/hr-app-*` screen
kits are the visual spec for every route. shadcn/ui + Tailwind v4 are the build
tools, but stock defaults are not the design — match the system, and flag
genuine gaps rather than improvising styling or component patterns.

**Translate the design to Tailwind — never port inline styles.** The design
project authors its components as reference JSX with inline `style={{ … }}`
referencing CSS variables (`var(--brand)` …). That is the _spec's_ idiom, not
ours: the DS is framework-neutral because it also feeds `apps/mobile`
(NativeWind). On web you **translate** it to Tailwind utility classes. Inline
`style` is reserved for genuinely dynamic values a class can't express (e.g. a
prop-driven `url()`), and even then the _behaviour_ (breakpoints, hover, focus)
stays in classes — inline styles can't do media queries or `:hover`.

- The design tokens are bridged into Tailwind's theme via a `@theme` block in
  `src/app.css`, so every token is a first-class utility: `bg-brand`,
  `text-muted`/`text-strong` (text _colors_ live under `--color-*`; `text-xl` etc.
  remain font _sizes_), `rounded-lg`, `shadow-xl`, `font-sans`, `tracking-tight`,
  and the custom `auth:` breakpoint. Keep `@theme` in sync with the design
  project's `tokens/*.css`.
- One design-system button: `src/components/ui/button.tsx` (`cva` over the tokens
  — variants `primary`/`secondary`/`neutral`/`ghost`/`danger`, `shape`
  pill/square). Use it; there is no separate `CdButton`.
- Reference implementations of the translation: `src/components/auth/*` and
  `src/routes/login.tsx`.

## Data, tables and forms

The three TanStack libraries below are **mandatory** patterns (see the root
`CLAUDE.md` "Web data, tables and forms" hard rules). Integration points:

- **TanStack Query** is already wired: `trpcReact` (`src/trpc.ts`,
  `@trpc/react-query`) over the shared `QueryClient` (`src/query-client.ts`),
  which is built in `getRouter()` and lives in RouterContext. Components fetch
  and mutate with `trpcReact.<proc>.useQuery()/.useMutation()`. Loaders and
  server functions may use the vanilla `trpc` client; reactive component data is
  always a Query hook.
- **TanStack Table** (`@tanstack/react-table`) renders all list/tabular data.
  Pagination/sorting/filtering are server-side in SQL (keyset cursors — see
  `@repo/trpc`), so tables run in manual mode
  (`manualPagination`/`manualSorting`/`manualFiltering`) and render the single
  page returned; they never sort or filter in the browser.
- **TanStack Form** (`@tanstack/react-form`) backs every form via `useForm` +
  `form.Field` + `form.Subscribe`, validated with the shared `@repo/trpc` Zod
  schemas through the standard-schema validator. `src/routes/login.tsx` is the
  reference example.

## Testing

- Unit/component: Vitest + jsdom + Testing Library (`src/**/*.test.tsx`).
- E2E: Playwright (`e2e/`, chromium, serial), boots `pnpm dev` on 3000.

Never `process.env` (use `@repo/env`), never `console.log` (use `@repo/logging`
on the server). Client vars must be `VITE_`-prefixed.
